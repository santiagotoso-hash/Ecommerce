# 49. KNOWN POTENTIAL ISSUES TO INVESTIGATE

The following are NOT confirmed bugs.

They are investigation points identified from the current controller/source inventory.

1. CategoryController converts a UUID string using +id.

2. Some endpoints have @ApiBearerAuth() but no AuthGuard.

3. DELETE /users/:id is authenticated but does not explicitly require Admin role.

4. DELETE /products/:id is authenticated but does not explicitly require Admin/Tester.

5. GET /products/seeder does not show authentication.

6. GET /category/seeder does not show AuthGuard.

7. POST /products/upload and POST /files/uploadImage/:id appear to overlap in file-upload functionality.

8. Cloudinary logic exists in config, users and files areas and should be reviewed for duplication.

9. File upload maximum is configured as 2,000,000 bytes while the error message says 200kb.

10. Cart and CartItem are specified in the business model but are not present in src.

11. Product/User/Order relationships must be verified directly in entities.

12. UUID usage must be consistent across entities, DTOs, controllers and repositories.

13. Category repository filename contains spelling mistakes:
    catogory.respository.ts

14. ProductsController imports CreateProductDto using a type-only import.

15. The project has both order entities and an older business specification mentioning Cart.

These points require source verification before fixing.

# 50. SECURITY RULES

Never expose:

* password hashes
* JWT secrets
* database passwords
* Cloudinary secrets
* API keys

Never place real .env values in this file.

Authentication and authorization must be treated separately:

Authentication:

"Who is the user?"

Authorization:

"What is the user allowed to do?"

@ApiBearerAuth() is documentation only.

@UseGuards(AuthGuard) provides authentication.

@UseGuards(RolesGuard) provides role authorization when combined with @Roles().
